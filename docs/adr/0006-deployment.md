# ADR-0006: Deployment

- Status: Accepted. The Dockerfile and `render.yaml` are written but have not been run on a host yet (see "Not yet verified").

## Context
The assessment asks for a deployed, working app. The design (HttpOnly cookies, CSRF, SameSite=Strict) needs the page and
the API on the same address. SQLite is a file, and free hosting disks are usually wiped on every deploy.

## Decision
- **One container, one address.** A multi-stage `Dockerfile` builds the Angular app, copies it into the Spring Boot jar's
  `static/` folder and runs the jar. Spring serves the pages and the API. `SpaForwardController` answers direct visits
  and reloads of Angular pages (`/insights`, ...) with `index.html`.
- **The app loads its own demo data.** On start, when `SEED_EMPLOYEES=true` and the table is empty, `EmployeeSeeder` runs
  `db/seed/employees.sql` (10,000 employees, one transaction, about 120 ms). The file is generated by
  `scripts/seed-employees.js --emit-sql`, the same generator used in development, and it produces the same data as
  `npm run db:seed` (same row count and salary total). Restarting never duplicates data.
- **Configuration from the environment** (ADR-0002): `JWT_SECRET` (at least 32 characters, no default, startup fails
  without it), `PORT` (set by the platform), `DB_URL`, `SEED_DEMO_USERS`, `SEED_EMPLOYEES`, rate-limit and token settings.
  Cookies are `Secure` unless `AUTH_COOKIE_SECURE=false` (only for plain http on a developer machine).
- **Behind the platform's HTTPS proxy** (`server.forward-headers-strategy=framework`): the real client IP is used by the
  rate limiter and the original scheme by cookies. This trusts the proxy's `X-Forwarded-*` headers.
- **Health check:** `GET /actuator/health` (public).

## Steps (Render)
1. Push the repository to GitHub.
2. Render dashboard: New > Blueprint > choose the repository. `render.yaml` creates a Docker web service with a random
   `JWT_SECRET`.
3. Wait for the build; open the service URL and sign in with a demo account (listed in the README).

Any host that runs a Docker image works the same way (set `JWT_SECRET`, expose the port it assigns).

## Consequences
- With no persistent disk, every restart recreates the demo data and discards edits. To keep edits, mount a disk at
  `/data` (the image already points `DB_URL` there).
- One instance only: SQLite allows one writer at a time and the rate limiter is in memory (ADR-0003, ADR-0005).
- Demo accounts and their public password exist in this build for reviewers; disable with `SEED_DEMO_USERS=false`.

## Not yet verified
- The Docker image has not been built here (Docker is not installed on the development machine). What was verified:
  the same steps run natively (build the Angular app, copy it into `static/`, `./mvnw package`, run the jar on an empty
  database): pages and deep links are served, 10,000 employees are loaded, sign-in and the API work, and a restart does
  not re-seed.
- `render.yaml` has not been used on Render.
